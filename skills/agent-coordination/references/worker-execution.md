# Worker routing and execution receipts

Ordinary engineering prefers this CLI execution path when task authority and the required-capability preflight below permit; an explicitly selected native, cloud or desktop environment wins. Execution choice does not replace bookkeeping: keep the existing task record and any supported native records and navigation for accountability and takeover. Missing required CLI access holds dependent dispatch, or after reconciliation uses an already-authorized alternative. This path controls only sessions owned by that task; it never takes over a human session, creates access, adds a second writer or changes user defaults.

## Select and pin
Keep provider/model choices in private task configuration. Each provider has `ordinary` and `involved` profiles with exact `model`, `effort` and `timeout_seconds`. Claude can additionally enforce `max_cost_usd`; this Codex adapter cannot enforce a dollar cap. Supply current supported model/effort capabilities and their evidence reference.

`agent_skills.worker_execution.select_route(policy, capabilities, provider=..., signals=..., reason=...)` selects the ordinary profile when no complexity signal applies. Architecture, ambiguous failures, high-risk review, multi-system work or repeated reasoning failure select the involved profile immediately. Do not require a cheap failed attempt when complexity is already known. An unavailable stronger route fails without a silent downgrade. The caller must assess task complexity; this helper does not infer it from arbitrary prose. An optional per-provider `effort_ceiling` (ordinary `medium`, involved `high` justified by a signal, ceiling `high`) makes any route above it fail with no fallback, and the route records the ceiling. A policy without one is the explicit compatibility path: its route records no ceiling and nothing above the capability receipt is enforced.

Before a dependent dispatch, `check_environment(required, receipt, environment_id=..., auth_context=..., route=..., now=..., max_age_seconds=...)` checks caller-supplied readiness metadata for that exact environment and execution/auth context. It never probes, opens connections or creates access. The receipt has exactly `environment_id`, `auth_context`, `observed_at_utc`, `source_ref`, `capabilities` `{name: {state: verified|blocked|unknown, source_ref}}` and `models`. Name each task's needs separately (`auth`, `repo:<name>`, `db:<name>`, `messaging:<name>`, `hosted-attachment`, `quota`). Absent or `unknown` stays unknown and blocks; a supported model/effort says nothing about database or messaging access, and token usage never establishes remaining quota. A blocked login in one context (a sandbox) is not an account-wide logout and cannot satisfy or veto another context; a mismatch, a stale receipt or an unsupported route blocks too. Only refs and the receipt hash are kept. Pass the result to `bind_route(..., readiness=..., required=..., environment_id=..., auth_context=..., now=...)`; it recomputes the gaps rather than trusting `ready`, and refuses before any launch. Declaring `required`, an environment, an auth context or `now` without `readiness` fails closed. Only a bind with none of these is the compatibility path: its route carries no environment check; say so instead of claiming readiness.

Use `bind_route(record, route, source_pin=..., decision_ref=...)`, then persist the existing record. The route names the reason, model, effort and time/cost bounds. The task owns the source pin. A resumed route/source change requires `change_ref`; preserve the previous route in its history. A stronger model never expands tools, data, export scope, publication or deployment authority.

## Dispatch and reconcile
1. `tasks.begin_dispatch` snapshots the pinned route on the existing outbox entry before launch. An unresolved launch blocks another. A routed resume needs the owned session ID; an existing session cannot be replaced by another fresh launch.
2. Construct `workers.Claude(model=..., effort=..., max_cost_usd=...)` or `workers.Codex(model=..., effort=...)` from that route. Commands require both model and effort; parser-only use needs neither. Verify the model-specific effort support before dispatch.
3. `workers.run` returns `RunResult`: state, stdout, stderr, exit code, PID and UTC start/finish. Existing `(state, stdout)` unpacking remains compatible. Preserve sanitized streams in the authorized task destination, not reusable skills. The new process group is bounded by timeout; only that owned group is terminated on timeout. Possible external effects remain uncertain.
4. Parse CLI output, then call `record_execution(record, dispatch_id, execution, parsed, receipt_ref=...)` and persist. This retains requested versus observed metadata and diagnostic hashes without raw streams. A timeout remains unresolved even if local termination succeeded. Reconcile through supported receipts before retrying; no private transcript files or socket protocol.
5. `Claude.launched(session_id, receipt)` accepts a supported CLI output/inventory receipt. False means unverified. Empty inventory does not prove no historical launch. This helper never reads private storage.
6. Read and validate the exact returned artifact, then call `consume_result` with its stdout hash and a parent readback reference. Terminal result, parent consumption and functional acceptance remain separate. The existing event reducer still checks current task/deliverable binding and acceptance.

## Human takeover and handback
`agent_skills.session_handoff` keeps one handoff on the existing `worker` record; it launches, opens, discovers and grants nothing. Receipts and the recorded writer are cooperative evidence, not a lock against a writer that ignores the record.
- `plan_handoff(provider, origin, destination)` returns only documented routes; any other pair raises:

  | Route | Continuity | ID | Human runs |
  |---|---|---|---|
  | Claude CLI → CLI | same session | local UUID | `claude --resume <uuid>` in the same workspace |
  | Claude CLI → Desktop | same session | local UUID | `claude --desktop --resume <uuid>` after the CLI exits (or `/desktop` inside an interactive session) |
  | Claude Desktop → CLI | same session | local UUID | `claude --resume <uuid>` after the Desktop writer exits |
  | Claude cloud → CLI | local copy; later local work does not sync back | cloud ID | `claude --teleport <id>` in a clean checkout of the same repo; branch pushed |
  | Codex CLI → CLI | same session | local UUID | `codex resume <uuid>` in the same workspace |
  | Codex CLI → Desktop | same session, only where the host can read and open that thread | local UUID | the host's supported thread-open action for the verified UUID |
  | Codex cloud → CLI | diff only, no session | cloud task ID | `codex cloud apply <id>` in a clean checkout |

  Codex CLI → Desktop has no CLI command or link: `codex app <path>` opens only a workspace, and the CLI has no `agents --json`. A host may expose native thread read/open (one Codex host offers `navigate_to_codex_page(threadId)`); that is a host tool call, not shell syntax, and is not available to CLI workers or every environment. Unsupported: Claude cloud → Desktop by ID, Codex Desktop → CLI, CLI-side session discovery. Never invent flags, links or listing commands.
- `request_takeover(record, provider=, origin=, destination=, source=, requested_ref=, requested_at_utc=, capability=None, host_ref=None)` needs the owned session and the route's ID kind (a cloud ID is never a resume UUID). A `thread-open` route also needs the caller's expected `host_ref` (never taken from the receipt; recorded as `expected_host_ref`) and `capability` `{provider, host_ref, session_ref, workspace_ref, action, state, source_ref, observed_at_utc}`: a current readback from that host of that exact session and workspace, `verified`, observed after the request; anything absent, stale, from another host or mismatched holds the route in that environment. Other routes reject both arguments. Opening the thread is not visual confirmation or acceptance. The request freezes `begin_dispatch` and `bind_route`; in-flight results still record. A second pending claim fails; `cancel_takeover` unfreezes.
- `release_to_human(..., destination=, observation=, checkpoint=, acceptance_ref=)` recomputes `takeover_gaps`: process `running|idle|exited|unknown` (same-session needs `exited`; unknown holds), observation after the request, saved checkpoint after quiescence naming the owned session, same repo, same workspace/branch/head for same-session, clean and pushed for copies, no uncertain dispatch. It sets the worker owner to `human`, so every dispatch is refused.
- `confirm_destination` records what the human saw (Desktop stays `pending-visual` until then); a copy names its own session, never the source. `hand_back` needs that confirmation, the human's writer quiescent and a new checkpoint; only then does the assistant own and resume its own session. It never adopts the human's copy.

Human checks before accepting: the CLI process has exited (no prompt, no `claude agents`/`codex agents` entry still running it); `git status` is clean where required and the branch/HEAD match the checkpoint; the session shown is the exact ID. Report back what you saw; say "hand back" explicitly to return the session.

## Evidence limits
Parsers retain runtime model/usage metadata and exposed effort. They never treat requested arguments or assistant claims as actual settings. Missing effective model/effort remains unknown. Model evidence has roles: `primary_models` come only from root runtime rows (Claude `system` init `model` and assistant `message.model` with no `parent_tool_use_id`; the Codex runtime start for the same conversation). Every other observed model, such as a tool's helper model or a sub-agent, is in `auxiliary_models`. Without root rows, `models` and `model_usage` are unattributed (`model_attribution: usage-only`). `record_execution` then sets `model_match`:
- exactly one primary model, equal to the requested one → match;
- a different primary, or conflicting primaries → mismatch, and the result is withheld, even when the requested model appears as auxiliary;
- no primary evidence → mismatch only when the requested model is absent from usage, match only when it is the sole model, otherwise unknown (`None`).

Unknown is not a verified match. Conflicting efforts withhold the result. Helper usage is a cost diagnostic, never quota. Claude's `--output-format json` returns only the result record, so a mixed run there stays unknown; stream output can attribute it. Retain original output for later investigation.

These pure functions do not authenticate caller-provided receipts or operate native notifications. Adoption requires an actual caller. Validate one isolated fresh run and one owned resumed run, with source pin, exact route, CLI/session/process identity, exit status, output hashes and parent readback. Test timeouts and ownership refusal without interrupting unrelated work. No healthy deployment or completed turn establishes broad adoption.
