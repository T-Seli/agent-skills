# Portable phases and observable proof

Use the existing task/spec and owner; this contract adds no dispatcher, tracker,
notification sender, temporary-file prohibition or execution authority.

## Select the phase, including local prototypes

Read the actual installed phase body before acting: blueprint for investigation
and options; implement for authorized changes, plus TDD for code; test-review for
independent review. UI design supplements these phases; it does not replace them.
Keep unresolved choices proposed. Missing Git is not permission to skip a phase.
For explicitly authorized non-Git work, bind the workspace, allowed paths, owner,
baseline copy/content hashes, accepted checks and existing task-local record before
editing. Use this record instead of Git-derived MAIN/DRAFT/TASK. Compare base/final
bytes or manifests instead of inventing commits.
Adapt only Git-dependent sync/worktree/diff/commit steps; retain scope, test-first
code checks, independent review and evidence. Never initialize a repo or widen
paths merely to satisfy a skill. A required Git integration/spec-mode gate still
holds until its supported route is agreed; this is not an escape from spec mode.

## Map principles to checks and bound the work

In the current spec use rows: principle/outcome | user task/state | action |
observable expected result/counterexample | exact artifact | evidence/limit.
For example, clear save feedback means edit, save and edit again: status follows
the actual saved snapshot. A screenshot alone cannot prove persistence or usability.
Keep aesthetic judgments and human accessibility acceptance distinct from metrics.
Use small tickets with one owner, paths and done-when checks. Parallelize only
independent ready slices; shared files and actual prerequisites are separate holds.
Before dispatch budget the complete path, including independent final retests,
across parent/children and concurrent activities. Reserve verification effort;
propose smaller scope or seek the missing decision before spending it on the first pass.
Use the existing [worker route](../../agent-coordination/references/worker-execution.md)
for task-fit model/effort, not automatic maximum effort. Retain requested and
runtime-observed choices separately; unavailable effective settings stay unknown.

## Propagate scope and preserve exact evidence

Copy allowed read/write/scratch/artifact roots and exclusions into worker briefs.
An explicit narrow path boundary also governs scripts and screenshots: use an
allowed scratch directory, or hold that write for a concrete scoped decision.
Otherwise normal authorized temporary storage remains allowed. Check actual
paths; do not redirect TMPDIR globally or delete user data to obtain compliance.
Persist reproducible commands/actions, results and artifact hashes in allowed
locations before cleanup. Give each round/revision its own evidence paths; do not
overwrite earlier screenshots or use mtime alone as source provenance.
Parent tests cannot resolve an independent-review obligation. The relevant critic
must retry the original finding and appropriate adjacent checks on the exact final
artifact, recording identity and actions/results; newly inspected screenshots apply
only to UI findings that need visual evidence, not unrelated backend reviews.
Without the required independent verification, retain the finding, owner, evidence
gap and next action; never infer convergence.

## Preflight the actual reply and recover durably

Apply the current user's output cap as well as applicable report limits. Count
the complete intended reply, including headings/tables, before sending; put detail
in the authorized artifact while keeping blockers/decisions/next action inline.
Use `agent_skills.evaluation_contract.measure_report` when available, or a
supported equivalent, to measure lexical words/lines; disclose an uncounted cap.
Measuring neither shortens text nor enforces native generation. Do not drop acceptance
limits or claim success just to fit. State any incompatible required format.
At a checkpoint retain task/spec/source, owner, pending effects, evidence cursor,
next action/checkpoint and actual capability/budget gaps in the existing record.
Dispatch, admission, execution, review and delivered result are separate receipts.
Reuse [state and checkpoints](../../agent-coordination/references/state.md): staged
notification intents are not sends or schedules. Verify the current event/readback
route; completion/disconnect support does not prove a universal idle event or
end-to-end delivery. Without a supported route name the next bounded reader and
checkpoint, not an always-on promise. Reconcile uncertain dispatch before retry.
