# Review and rollout

1. Review the source diff and schema against the existing project log conventions. Run `tests/check.sh` and the unit suite. Do not change active adapter installations during review.
2. Choose one existing task with a known record owner for a synthetic pilot. Pin the source commit and runtime version. Use the approved private checkout identity and run `init` after a fresh clone to restore narrow event-file permissions. Use a separate local history checkout, a new event file and a restricted packet with no customer content. Verify a fresh reader can reconstruct the overview and all events.
3. Reconcile the private history remote before each publication: fetch, compare the task file and event IDs, stop on unexpected changes, and use normal review/approval to publish. No force push. On uncertain publication, fetch and look for the event ID before retrying.
4. After approval, update adapters in an idle window, preserving their prior installed targets for rollback. Keep local project logs and existing record commits while pilots run. Existing compact Markdown snapshots remain readable and need no bulk migration.
5. Measure retrieval and corrections on real approved tasks. Turn recurring failure modes into sanitized regression cases with a stated expected outcome; compare candidate skill version to the pinned baseline, review the proposal, then separately approve any skill change. Roll back to the prior pin if behavior regresses.

Sources informing fields and boundaries: [OpenTelemetry log data model](https://opentelemetry.io/docs/specs/otel/logs/data-model/), [sensitive data handling](https://opentelemetry.io/docs/security/handling-sensitive-data/), [Anthropic long-running agent harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents), [Anthropic agent evaluations](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents), and [OpenAI agent evaluations](https://developers.openai.com/api/docs/guides/agent-evals). These sources inform event identity, context, resumption and evaluation; they do not prescribe this Git checkout design.

Current integration limits: the new skill is not in the install catalog or native adapter package; no adapter loads it yet. The compact local `agent_skills.history` and central event writer remain separate, linked by references only. Acknowledgment durability after a remote push, legacy Markdown migration, and a real sanitized incident regression case need pilot design and review. No remote write path is provided by this tool.

Existing `tasks/*.md` and any user-edited view are preserved. Do not render the live cloud-owned pilot record until its owner agrees on a refresh point.
